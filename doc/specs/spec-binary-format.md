# sfvcs バイナリフォーマット・カノニカルシリアライズ詳細仕様書

本書は `sfvcs` における全オブジェクトのデータモデル、バイナリレイアウト、カノニカルシリアライズ（正規化エンコーディング）方式および CID（Content ID）計算手順を定義する仕様書である。

本仕様に従って実装されたエンコーダは、異なる言語・プラットフォーム・実装であっても、同一データに対して1ビットの狂いもなく同一の CID を生成することを保証する。

---

# 1. 基本エンコーディング規則

## 1.1 エンディアンと整数表現
- **エンディアン**: すべての多バイト整数は **ビッグエンディアン（Big-Endian / Network Byte Order）** とする。
- **符号なし整数**:
  - `uint8`: 1バイト固定
  - `uint16`: 2バイト固定
  - `uint32`: 4バイト固定
  - `uint64`: 8バイト固定
  - `varint` (Variable-length Integer): Protocol Buffers 形式の unsigned LEB128 (7ビットごとに区切り、最上位ビットで継続を表現)。小さな整数のバイト数を短縮するために使用する。

## 1.2 文字列表現
- **文字列**: UTF-8 エンコーディングを使用する。
- **文字列レイアウト**:
  ```
  [length: varint][utf8_bytes: length バイト]
  ```
- **パス文字列**:
  - ディレクトリ区切り文字は常に `/`（POSIX形式）を使用する。
  - 先頭および末尾の `/` は禁止（ルート以外）。
  - `.` や `..`、連続する `//` は正規化により排除する。

## 1.3 CID (Content Identifier) 表現
- **CID アルゴリズム**: デフォルトは **SHA-256**（32バイト）。
- **CID データ構造**:
  ```
  [algo_id: uint8][hash_bytes: N バイト]
  ```
  - `algo_id = 0x01`: SHA-256 (32バイト)
  - `algo_id = 0x02`: BLAKE3 (32バイト)（将来拡張用）
- 本バイナリ内での CID 参照（子ノード CID など）は、上記 `[algo_id][hash_bytes]` の 33 バイト固定長で保持する。

# 2. オブジェクトの全体構造とドメイン分離

セキュリティおよびハッシュ衝突防御のため、全オブジェクトはハッシュ計算時に **ドメイン分離タグ (Domain Separation Tag)** をプレフィックスとして付与する。

## 2.1 シリアライズ構造
```
+-------------------------------------------------------+
| Domain Tag (4 bytes ASCII)                            |
+-------------------------------------------------------+
| Format Version (uint8)                                |
+-------------------------------------------------------+
| Payload Length (varint)                               |
+-------------------------------------------------------+
| Object Type Payload (可変長)                          |
+-------------------------------------------------------+
```

## 2.2 ドメインタグ一覧
| オブジェクト種別 | ドメインタグ (ASCII 4 bytes) | Format Version | 説明 |
|---|---|---|---|
| Chunk | `SFCK` | `0x01` | 生バイトデータチャンク |
| Sequence Node | `SFSQ` | `0x01` | ファイル内容のシーケンス木ノード |
| File Node | `SFFL` | `0x01` | ファイルメタデータおよびシーケンスルート参照 |
| Directory Node| `SFDR` | `0x01` | ディレクトリエントリ集合 |
| Commit | `SFCM` | `0x01` | コミットオブジェクト |
| Symlink | `SFSL` | `0x01` | シンボリックリンク |

## 2.3 CID 計算式
```
CID_SHA256 = SHA256( DomainTag || FormatVersion || PayloadLength || Payload )
CID_Bytes  = 0x01 (SHA-256タグ) || CID_SHA256 (32バイト)  [計33バイト]
```

# 3. オブジェクト別ペイロード定義

## 3.1 Chunk Object (`SFCK`)
ファイル内容を分割した末端（Leaf）の生バイトデータ。

### ペイロードレイアウト
```
+-------------------------------------------------------+
| Raw Data Length (varint)                              |
+-------------------------------------------------------+
| Raw Data Bytes (可変長)                              |
+-------------------------------------------------------+
```

---

## 3.2 Sequence Node (`SFSQ`)
ファイル内容を表現する Persistence Sequence Tree の中間ノードまたは葉直上ノード。

### ペイロードレイアウト
```
+-------------------------------------------------------+
| Node Flags (uint8)                                    |
+-------------------------------------------------------+
| Logical Subtree Byte Length (varint)                  |
+-------------------------------------------------------+
| Children Count (varint)                               |
+-------------------------------------------------------+
| Array of Child Subtree Logical Lengths (varint x N)   |
+-------------------------------------------------------+
| Array of Child CIDs (33 bytes x N)                    |
+-------------------------------------------------------+
```

#### Node Flags 仕様
- `0x01` (`FLAG_LEAF_CHILDREN`): 子要素がすべて `Chunk` (SFCK) である場合。
- `0x02` (`FLAG_INTERNAL_CHILDREN`): 子要素がすべて下位の `Sequence Node` (SFSQ) である場合。

---

## 3.3 Symlink Object (`SFSL`)
シンボリックリンクのターゲットパスを保持する。

### ペイロードレイアウト
```
+-------------------------------------------------------+
| Target Path Length (varint)                           |
+-------------------------------------------------------+
| Target Path Bytes (UTF-8, 可変長)                    |
+-------------------------------------------------------+
```

---

## 3.4 File Node (`SFFL`)
ファイルのメタデータおよびコンテンツ（Sequence Root または Small Inline Bytes）を保持する。

### ペイロードレイアウト
```
+-------------------------------------------------------+
| File Flags (uint8)                                    |
+-------------------------------------------------------+
| Unix Mode / Permissions (uint32)                      |
+-------------------------------------------------------+
| Total File Size in Bytes (uint64)                      |
+-------------------------------------------------------+
| Content Storage Type (uint8)                          |
+-------------------------------------------------------+
| Content Payload (インラインバイト OR Content Root CID) |
+-------------------------------------------------------+
```

#### File Flags 仕様
- `0x01` (`FILE_EXEC`): 実行可能ファイル権限 (例: `0755`)

#### Content Storage Type 仕様
- `0x00` (`CONTENT_INLINE`):
  - ファイルサイズが小規模インライン閾値（デフォルト: **1,024 バイト以下**）の場合に採用。
  - Payload 構造: `[length: varint][raw_bytes: length]`
  - Sequence Node や Chunk を生成せず直接バイト列を格納する。
- `0x01` (`CONTENT_SEQUENCE_ROOT`):
  - 1,024 バイト超の通常ファイル。
  - Payload 構造: `[content_root_cid: 33 bytes]` (SFSQ または SFCK の CID)

---

## 3.5 Directory Node (`SFDR`)
ディレクトリ直下のファイルおよびサブディレクトリのリスト。
**正規化ルール**: エントリは名前に基づき **UTF-8 バイト順（Lexicographical order）** で昇順ソートされていなければならない。重複名は禁止。

### ペイロードレイアウト
```
+-------------------------------------------------------+
| Entry Count (varint)                                  |
+-------------------------------------------------------+
| Array of Entries (ソート済み)                         |
+-------------------------------------------------------+
```

#### Entry の構造
```
+-------------------------------------------------------+
| Entry Name Length (varint)                            |
+-------------------------------------------------------+
| Entry Name Bytes (UTF-8)                              |
+-------------------------------------------------------+
| Entry Type (uint8)                                    |
+-------------------------------------------------------+
| Target CID (33 bytes)                                 |
+-------------------------------------------------------+
```

#### Entry Type 仕様
- `0x01` (`ENTRY_FILE`): File Node (`SFFL`) を参照
- `0x02` (`ENTRY_DIRECTORY`): Directory Node (`SFDR`) を参照
- `0x03` (`ENTRY_SYMLINK`): Symlink Object (`SFSL`) を参照

---

## 3.6 Commit Object (`SFCM`)
コミットメタデータおよびスナップショット（ルートディレクトリ）の参照。

### ペイロードレイアウト
```
+-------------------------------------------------------+
| Root Directory CID (33 bytes)                         |
+-------------------------------------------------------+
| Parent Count (uint8)                                  |
+-------------------------------------------------------+
| Parent Commit CIDs (33 bytes x Parent Count)          |
+-------------------------------------------------------+
| Author Name (Length-prefixed String)                  |
+-------------------------------------------------------+
| Author Email (Length-prefixed String)                 |
+-------------------------------------------------------+
| Author Timestamp Unix Epoch Seconds (int64)           |
+-------------------------------------------------------+
| Author Timezone Offset Minutes (int16)                |
+-------------------------------------------------------+
| Committer Name (Length-prefixed String)               |
+-------------------------------------------------------+
| Committer Email (Length-prefixed String)              |
+-------------------------------------------------------+
| Committer Timestamp Unix Epoch Seconds (int64)        |
+-------------------------------------------------------+
| Committer Timezone Offset Minutes (int16)             |
+-------------------------------------------------------+
| Commit Message Bytes (Length-prefixed UTF-8 String)   |
+-------------------------------------------------------+
```

# 4. バリデーションと完全性検証ルール

すべての実装は、オブジェクトのロード時および `sfvcs fsck` 実行時に以下のルールを検証しなければならない。

1. **CID 一致性**: オブジェクトバイト列から計算した CID と、格納されているファイル名/インデックスの CID が厳密に一致すること。
2. **正規化検証**:
   - `SFDR`（Directory）内のエントリが正確に UTF-8 バイト昇順に並んでいること。
   - `SFSQ`（Sequence）内の Logical Length の合計が `Logical Subtree Byte Length` と正確に一致すること。
3. **型参照の正当性**:
   - Directory の `ENTRY_FILE` は `SFFL` オブジェクトを指していなければならない。
   - Directory の `ENTRY_DIRECTORY` は `SFDR` オブジェクトを指していなければならない。
   - Sequence Node の `FLAG_LEAF_CHILDREN` 時、全参照先 CID は `SFCK` オブジェクトでなければならない。
